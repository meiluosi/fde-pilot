# 衔接

本 Skill 可独立运行。有上游产物时手动读取，无工具或仓库依赖。记录输入路径、版本/哈希和读取日期；未提供的文件标“未提供”，不模拟读取成功；不改上游原件。多批输入同名编号时加前缀（`demo:`、`framing:`、`ramp:`），见 [series.md](series.md)。

## 承接 fde-demo（Proceed 复盘）
| Demo 复盘字段 | 用在试点的哪里 |
|---|---|
| 已换到的授权与对接人 | 方案“来源与交接”“数据与授权” |
| 尚未拿到的授权 | 启动检查，未到位不启动 |
| 三轴仍未验证的假设 | 方案“假设”H# |
| 失败样例清单 | 护栏与停止条件（S#）、适格案件的排除或分层 |
| 共同作者清单 | 试点参与者与内部支持者 |
| 反向信号清单 | 期中检查要盯的阻力与数据用途约定 |
| 现场提出的需求变更 | 范围与“不包含” |
| 原始基线与口径 | 指标字典的基线 |

demo 的结论若不是 Proceed，先问清为什么要启动试点；通常应回到 Demo 补验证。

## 承接 fde-problem-framing
| 上游产物 | 用在试点的哪里 |
|---|---|
| 定义卡“怎么算成功”、指标字典 | 指标字典 M#，同口径 |
| 定义卡“本期不做” | 方案“不包含” |
| 验证计划 V* | 假设 H#；与指标的对应关系 |
| 风险与退出 | 护栏与停止条件 |
| 证据台账 | 基线来源 |

## 承接 fde-ramp
活动表和 corrections 决定适格任务的定义、角色和交接；一线联系人是参与者和访谈对象。

## 回写
- 被推翻或修订的假设、口径 → 定义卡与验证计划（fde-problem-framing 的修订流程）。
- Demo 阶段判断被试点推翻（例如 Demo 的“已验证”在试点中站不住）→ fde-demo 的复盘，写成回写建议。
- 客户纠正的流程、术语 → 活动表与行话表（fde-ramp 的修订）。

## 交给后续阶段
Proceed 的成效报告至少带出：已验证的范围与未验证的范围；护栏事件与处置；基线与口径；运维与责任归属；仍需客户决策的事项。正式交付与推广阶段的 Skill 尚未发布。
