# 运行期预警

期中检查看的是“要不要停、要不要调”，不是“效果好不好”。结论性判断留到判定时点，按预登记的判据做。

## 预警信号
| 信号 | 可能含义 | 动作 |
|---|---|---|
| 有效使用率逐周下降 | 新奇效应消退、体验差、被绕开 | 访谈未使用者，区分“不适格”“不会用”“不想用” |
| 使用集中在少数人 | 自选高手；其他人有顾虑 | 查是否有数据用途顾虑；分层报告 |
| 回退人工比例上升 | 某类案件系统处理不了 | 归类失败模式，对照 Demo 的失败样例 |
| 复核时间上升 | 输出质量不够，复核负担变重 | 把复核时间计入业务指标，评估是否仍净节时 |
| 绕过行为（用别的工具、线下处理） | 流程不顺或有抵触 | 访谈，查是否与考核、责任有关 |
| 严重错误出现 | 护栏被触及 | 对照停止条件，按事前登记的动作执行 |
| 数据缺口（日志缺失、口径变化） | 后续无法判定 | 立即补采集或修正口径，并记录变更 |
| 范围蔓延（有人想加功能、加人群） | 试点被拉成上线 | 记入变更记录，按方案审批；不静默扩大 |

## 期中检查产出
- 指标现值（带分子/分母/窗口），不作成败判断；
- 学习期是否结束；
- 停止条件：未触发 / 已触发（编号、时间、动作）；
- 预警信号与处理；
- 方案变更（追加记录，不替换判据）；
- 下一次检查日期。

## 触发停止条件时
立即按方案动作执行（暂停、回退、通知责任岗位），记录事件，不等到结束判定。成效报告里必须写明触发情况，Proceed 不得与已触发且未处置的停止条件并存。
