# 三轴状态与建议结论

## 三轴
| 轴 | 回答什么 | 对应指标层 |
|---|---|---|
| 使用与采用 | 适格的人在适格的任务里是否真的在用，是否持续 | 使用 |
| 业务效果 | 同口径下，端到端工时、差错、成本是否改善，改善能否归因于试点 | 业务（含质量类的技术指标） |
| 护栏与可持续 | 护栏是否守住；运维、复核、责任是否撑得住试点之后 | 护栏 |

## 状态规则
引用记录 ID（来自[试点日志](../templates/pilot-log.md)）。只有**在方案中事前登记的指标 ID**对应的记录才可作证据；事后新增的指标只能列为探索性发现。

| 状态 | 条件 |
|---|---|
| 已验证 | 至少 2 条符合该轴要求的独立记录，均带样本数/分母；没有未解决的反向信号；该轴的附加条件满足 |
| 部分 | 至少 1 条行为、观测、抽检、事件或访谈类记录 |
| 未验证 | 没有可引用记录，或只有解读、转述 |
| 被推翻 | 至少 1 条直接反证，类型为日志指标、对照观测、抽检复核或事件 |

各轴“已验证”的要求：

| 轴 | 可计入类型 | 附加条件 |
|---|---|---|
| 使用与采用 | 日志指标、对照观测（使用层指标） | 覆盖稳定窗口，不只学习期 |
| 业务效果 | 对照观测、抽检复核、日志指标（业务/技术层指标） | 至少 1 条为对照观测或抽检复核；因果归因为“有对照”。无对照或前后对比，最高“部分” |
| 护栏与可持续 | 日志指标、抽检复核、事件（护栏层指标） | 没有触发的停止条件；严重错误有专项样本，不只看平均 |

“已验证”的范围始终限于所写的人群、案型、时间窗。小样本的“已验证”只表示机制成立，不代表总体。

## 建议结论
| 结论 | 条件 | 必须同时写 |
|---|---|---|
| Proceed | 三轴均已验证，且无触发的停止条件 | 扩大范围建议：对象、边界、仍未验证的假设；不是上线授权 |
| Iterate | 方向未被推翻，但至少一轴不足 | 补验证：补哪一轴、延长或怎样改；下次改什么 |
| Pivot | 假设、场景或用户被推翻，出现了更值得做的发现 | 转向：新方向及依据；被推翻内容如何留底 |
| Stop-Defer | 触发停止条件，或缺少继续的条件 | 重开条件 |

`scripts/check_readout.py` 会检查以上条件，违反时报错。这是规则检查，不是业务审批。最终由客户业务负责人决定。

## 不要这样判断
- 不因使用量上升而判业务有效。
- 不因“准确率高”而忽略复核与纠错时间。
- 不因试点期间效果好而外推到全量、其他案型或其他人群。
- 不因结果不佳而更换指标或判据。
- 不把“未验证”写成“被推翻”。没证据支持不等于有证据反对。
- 不把 Proceed 写成上线授权，也不把“试点成功”当作可以绕过正式交付的风控与合规流程。
